# Fantasyfootball code and security audit — 2026-11-14

The audit repaired confirmed authorization, privacy, database privilege, dependency, and reliability defects. The application is a stronger single-league pilot after these changes; it is **not yet ready for unrestricted multi-league accounts or paid league credits**. The launch blockers below are substantive engineering work, not a request to finish the new-league creation UI.

## Confirmed findings and repairs

| Priority | Finding and consequence | Repair and status |
| --- | --- | --- |
| High | Signed app cookies outlived provider logout/recovery because they did not identify a revocable provider session. | Bind cookies to a verified Supabase session ID; recheck live provider session, account state, and league membership. Logout revokes the provider session before clearing cookies. Password recovery revokes other sessions. Independent production signing secret required. Application changes require deployment and re-login. |
| High | Historian database role had SELECT access to approximately 102 public tables, including private application data. Generated SQL was guarded by insufficient text checks. | Live role now has SELECT on exactly nine history tables, no public-table writes, and no public-function EXECUTE. Application uses AST validation/reserialization, a fixed table/function/type allowlist, verified TLS, a read-only transaction, role assertion, timeouts, and row/result-size caps. Historian is explicitly restricted to its configured CFC league. |
| High | A deployed administrative ingestion worker accepted ordinary valid JWTs without service authorization and allowed unbounded work. | `quick-worker` v3 deployed with service-credential authorization, bounded bodies/upstream responses/pages/deadlines, safe pagination, fixed origins, generic errors, and idempotent upserts. Unauthenticated live probe returns 401. Source and three tests added to the repository. |
| High | Draft submissions could target an unowned slot or overwrite an existing result; unpublished selections leaked through broader data paths. | Validate authoritative slot ownership, cursor, team/player identity, and immutable completed picks; compare-and-swap skipped picks and stale clock changes. Filter unpublished picks from shared snapshots and narrow direct database SELECT policy. Remaining cross-write atomicity is a launch blocker below. |
| High | Trade requests trusted submitted asset metadata/ownership and racing transitions. | Canonicalize assets from authoritative league data at create/accept, reject invalid transitions and prototype keys, and condition terminal/counter transitions on pending status. Cross-offer locking/atomic acceptance remains required. |
| Medium | Public account preparation endpoint disclosed invitation/account existence and only searched the first 100 Auth users. | Remove endpoint. Use explicit sign-in/invited-signup choices and indistinguishable noninvite signup responses. No outsider Auth user is created. Real HTTP smoke assertions added. |
| Medium | Private historian conversations and other browser state were not consistently isolated by account and league; late responses could overwrite another conversation. | Shared account/league storage scope gated by live authorization; keyed provider remount; safe hydration and response targeting. Unattributed legacy browser history is retained but is not automatically displayed to another account. |
| Medium | Middleware path exemptions and obsolete missing-schema fallbacks weakened defense in depth. | Exact public-route matching, CSRF before exemptions, bounded cloned JSON, and fail-closed membership/rate-limit behavior. Handler-level authorization remains authoritative. |
| Medium | Current-main dependency audit reported 14 vulnerabilities, including one critical and six high. | Upgrade Next.js/its ESLint configuration to 16.4.6; update lockfile; narrow transitive minimatch override. Final npm audit reports zero known vulnerabilities. |
| Medium | Twelve live database functions had mutable search paths. | Fixed explicit paths; all twelve corresponding advisor warnings cleared. |
| Reliability/maintenance | Duplicate timer/fetch/state paths, unreachable modules, stale polling, fabricated fallback advice, and unchecked ingestion JSON. | Remove 14 unreachable source modules (2,103 lines); consolidate clocks, browser scope, ingestion HTTP/parsing; fix stale replies/timer drift/cached history traversal; expose unavailable states instead of invented scouting advice. |

Additional hardening: server-only imports for privileged modules; API private/no-store headers; disable framework identification; baseline CSP for framing, objects, base URI and form targets; conservative AI reservation when provider usage is missing; request cancellation propagated to AI fetches. This is a **partial CSP**, not a complete script-execution/XSS policy.

## Deployment and re-check runbook

1. Use the audit branch based on current GitHub main. Review the diff and pass CI. Keep the original dirty local checkout separate. Never copy its older schema/code over current production.
2. Read `supabase/operations/README.md` and compare live migration history. Historian privilege hardening and worker v3 are already live. Do not blindly mark migrations applied or removed: production also has historical timestamp migrations outside the repository's three-digit application sequence. Reconcile their exact SQL/history before relying on unattended `supabase db push`.
3. Verify the session-activity RPC and draft visibility policy from migration 021 exist and match the operation record **before application rollout**. The SQL is rerunnable and contains validation queries. It does not rebuild or drop warehouse tables.
4. Configure server secrets through hosting: a separate random `AUTH_SESSION_SECRET` of at least 32 characters, existing Supabase credentials, existing `AUDIT_HASH_KEY`, `ANTHROPIC_API_KEY`, reviewed AI budgets/prices, `HISTORIAN_LEAGUE_ID=1328902558617473024`, and an `LLM_DATABASE_URL` authenticating as `llm_reader` with a trusted TLS chain. Never use a service/postgres connection for historian queries or prefix a secret with `NEXT_PUBLIC_`.
5. On a disposable/staging environment run `npm ci --ignore-scripts`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run audit:dependencies`, `npm run build`, and `npm run test:framework-auth`. Run the existing staged Supabase rollout suite with Docker; it now covers 012–021, legacy fail-closed behavior, upgrade, clean reset, pgTAP, and concurrency. Do not run fixture-creating scripts against production.
6. Deploy the reviewed app. Existing app cookies deliberately require re-login. Verify real invited signup, sign-in, normal navigation, logout plus replay rejection, recovery plus old-session rejection, member/commissioner boundaries, hidden picks, and historian queries. Inspect latency and logs; do not log tokens, passwords, emails, or provider/database error bodies.
7. Re-sync history using the existing authenticated admin/cron workflows. Re-running the Edge worker performs idempotent upserts; it now requires the service bearer credential. Do not embed it in URLs/browser calls. This audit does not replace the existing Sleeper actual-results sync or traded-pick history semantics.
8. For rollback, redeploy the last known application revision only after understanding its old session format; rotate/expire session cookies if necessary. Keep the restrictive database grants/policy unless a verified compatibility issue requires a narrowly reviewed change. Do not restore broad historian privileges merely to make a failed query succeed.

## Research and repeatable audit method

Use [OWASP ASVS](https://asvs.owasp.org/) for verification coverage and the [OWASP secure review guide](https://cheatsheetseries.owasp.org/cheatsheets/Secure_Code_Review_Cheat_Sheet.html) and [WSTG](https://owasp.org/www-project-web-security-testing-guide/) for manual evidence and adversarial tests. Threat-model guest, member, commissioner, background worker, AI output, and compromised dependency separately; trace each to privileged database/provider actions. Scanner output is triage input, not a verdict.

The tool selection follows primary documentation: [Semgrep](https://semgrep.dev/docs/getting-started/quickstart), [Gitleaks](https://github.com/gitleaks/gitleaks), [Knip](https://knip.dev/overview/getting-started), [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/), [Next security advisories](https://github.com/vercel/next.js/security/advisories), and [GitHub Actions hardening](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions). Knip candidates were checked against actual imports/routes before deletion; operational scripts and fixtures were not deleted just because an application import graph cannot reach them.

Database decisions used the live catalog and [Supabase RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security), [Supabase sign-out semantics](https://supabase.com/docs/reference/javascript/auth-signout), and [node-postgres TLS behavior](https://node-postgres.com/features/ssl). AI prices were checked against [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing). Payment design recommendations follow [Stripe security guidance](https://docs.stripe.com/security/guide) and [webhook documentation](https://docs.stripe.com/webhooks).

Reusable review prompt:

> Audit the exact commit and deployment, preserving unrelated work. For each trust boundary, trace actor-controlled input through authentication, authorization, validation, and the privileged sink. Require file/line or live catalog evidence, exploit preconditions, impact, and a reproducible negative test before calling a finding confirmed. Check tenant scope, direct database access, revocation, races/idempotency, secrets, AI costs, and browser persistence. Inspect information_schema before SQL. Repair the smallest coherent unit using established shared code; verify behavior and denied behavior. Separate confirmed defects, false positives, untested assumptions, deployed changes, and future product work. Never equate a green scanner with enterprise readiness.
